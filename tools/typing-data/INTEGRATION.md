# 汉字打字练习：接入说明（给另一个会话 / 开发者）

这份文档描述 `typing.html` 这个打字练习的全部数据和规则，目的是让另一个会话在不看聊天记录的情况下，把它接进 Hanzumio App（Flutter）或其他产品。所有内容都在仓库 `wangjiaqi78910/hanzumio` 的分支 `claude/chinese-typing-page-gwn6s1` 上。

## 1. 现有的东西

| 路径 | 内容 |
| --- | --- |
| `typing.html` `typing.js` `typing.css` | 网页版练习，纯静态、无依赖，支持中 / 英 / 韩界面，浅色与深色 |
| `typing-data/hsk1.js` … `hsk7-9.js` | 题库，每级一个文件（HSK 1、2、3、4、5、6、7-9），共 22,929 句 |
| `audio/hsk1/` … `audio/hsk5/` | 句子录音 MP3，文件名 `<题目id>-<行号>.mp3`；HSK 6、7-9 待补 |
| `audio/README.md` | 录音文件的命名和托管规则 |
| `tools/typing-data/` | 从 HSK 词表 Excel 重建题库的脚本（`README.md` 有步骤） |
| `tools/typing-data/recording/hsk*.txt` | 录音清单：每行「文件名 ⇥ 句子」 |

网页版的行为就是产品规格，接入时以它为准；在浏览器里打开 `typing.html` 即可体验（需要通过 HTTP 访问，`file://` 打不开按级别加载的数据）。

## 2. 题库数据格式

每个文件是一行 JavaScript：`window.HANZUMIO_TYPING_LEVELS=…;window.HANZUMIO_TYPING_LEVELS["1"]={…};`。去掉第一个 `]=` 之前的内容和末尾的分号，剩下的就是 JSON：

```json
{
  "level": "1",
  "words": {
    "学生": ["xuésheng", "n", "student", "학생"],
    "行|háng": ["háng", "n", "line / profession", "줄 / 직업"]
  },
  "items": [
    ["ce53b631", "d", "爱", [
      ["你 爱 吃 什么 ？", "nǐ ài chī shén-me", "What do you love to eat?", "무엇을 먹는 걸 좋아해요?"],
      ["我 爱 吃 米饭 。", "wǒ ài chī mǐ-fàn", "I love to eat rice.", "저는 밥 먹는 걸 좋아해요."]
    ]]
  ]
}
```

- `items` 里每一项：`[id, 类型, 本题词, 行列表]`。类型 `d` 是一问一答对话（两行），`e` 是例句（一行）。id 是 8 位十六进制，按中文内容算出，重建题库时不变。
- **一行就是一道题**。网页版把对话的两行拆成前后两题，答句题的顶部显示上一句（问句）的中文和译文当上下文。
- 每行：`[w, p, en, ko]`。
  - `w`：句子，词与词之间一个空格。标点、数字、字母也是独立的「词」，但不要求输入，原样显示。只含汉字的词才是要打的。
  - `p`：只给汉字词的拼音，顺序与 `w` 里的汉字词一致；一个词内部音节用 `-` 分开，一个字一个音节；儿化的「儿」写作 `r`（哪儿 → `nǎ-r`）。
  - `en` / `ko`：这一行的译文，作为题面。两种都有；界面语言决定显示哪种。
- `words`：这一级句子里用到的词的词卡，键是汉字；同形异音的词再加一条 `汉字|拼音`（小写、不含空格和撇号）。值 `[拼音, 词性代码, 英文释义, 韩文释义]`。查词时先用 `汉字|该词在这句里的拼音`（把 `p` 里的音节去掉 `-` 并小写），查不到再用 `汉字`。
- 词性代码：n 名词 v 动词 a 形容词 d 副词 r 代词 m 数词 q 量词 p 介词 c 连词 u 助词 i 叹词 o 拟声词 af 词缀 ci 成语 x 短语。
- 文件大小：HSK1 约 120 KB … HSK7-9 约 3.2 MB（gzip 后 1.3 MB），网页按级别按需加载。

## 3. 判分规则（网页版的实际行为，接入时请保持一致）

两种输入方式，由用户切换：

**拼音模式**（面向外国学习者，像输入法一样）
- 只打字母即可：`nihao` 算对。**默认不要求声调**。
- 可以连着打整句 `woshixuesheng`：当前空格的字母正好打完这个词时，多出来的字母自动流到下一个空格；按空格也可以跳到下一个词；最后一个词上按空格或回车提交。
- 声调可选：用数字 `ni3` 标调，输入时实时变成 `nǐ`；标了就检查，标错显示黄色（拼音对、声调错），不标不扣分。设置里可切换成「必须写声调」（这时没标调的非轻声音节算声调错）。
- `ü` 打 `v` 或 `ü`；在 j q x y 后面打 `u` 也行。儿化写 `nar`、`naer`、`nar3` 都算对；儿化音节后面的数字算前一个音节的声调。
- 一、不、个 的变调（yī/yí/yì、bù/bú、gè/ge）都算对；轻声音节标不标调都算对。
- 逐字母比对：去掉空格、撇号后，按正确答案的音节逐个消耗用户字母，字母对不上就是「写错」（红）。
- 大小写不区分。

**汉字模式**
- 用系统中文输入法打字。输入法选字时按的空格、回车不能当作「跳词」「提交」（网页版用 `isComposing` / keyCode 229 判断）。
- 一次打出多个词时，多出的字自动流到后面的空格（按每个词的字数切）。
- 判分：去掉空格和标点后与正确汉字完全相同才算对。

**通用**
- 标点、数字、字母不用打，原样显示。
- 提交后：对的绿、声调错黄、写错或没写红；每个词下面显示汉字和带声调的拼音（拼音模式）或拼音（汉字模式）；下方显示每个词的词卡（词性、拼音、释义），本题词高亮。
- 「再练一遍」只清空错的词；「看答案」（Esc）填入当前词的答案并标记为已看。
- 一道题第一次提交的结果计入「答对 / 答错」，重练不改变。
- 提示有三档：不提示 / 空格上方提示（拼音模式显示汉字、汉字模式显示拼音；默认）/ 词卡提示（提交前就显示所有词卡）。
- 练习记录（每题对错、当前位置、乱序种子）只存本地，网页版用 `localStorage` 键 `hanzumio-typing-v3`，题的键是 `<题目id>:<行号>`。

## 4. 录音

- 路径 `audio/hsk<级别>/<题目id>-<行号>.mp3`，例如 `audio/hsk1/ce53b631-0.mp3`。单声道 MP3，每个 3–40 KB，HSK1–5 共 7,834 个、117 MB；全部约 2.3 万句、估计 350 MB。
- 题目出现时自动播放（设置可关），Ctrl 或喇叭按钮重听；没有文件的句子按钮隐藏（网页版靠请求 404 判断）。
- 网页版可以用 `window.HANZUMIO_AUDIO_BASE = 'https://…/'` 把录音指到别的存储；App 可以随包内置、或按级别下载。
- 还缺的录音见 `tools/typing-data/recording/` 清单与实际文件的差集（HSK1–5 目前缺 252 句，HSK6、7-9 全部待录）。

## 5. 两种接入方式

**A. WebView 嵌入（最快）**：App 内打开托管的 `typing.html`（合并到 `main` 后由 GitHub Pages 发布）。URL 参数可以预设界面：`typing.html?level=2&ui=ko&mean=ko&mode=py&hint=cards&tones=req&autoplay=0&shuffle=1`（level：1–6、7-9；ui：zh/en/ko；mean：en/ko；mode：py/hz；hint：none/cross/cards；tones：req/opt；autoplay、shuffle：0/1）。参数会写进该 WebView 的设置，之后不带参数打开也保持。缺点：练习记录在 WebView 的 localStorage 里，与 App 数据不互通；离线需要自己缓存数据和录音。

**B. 原生实现（Flutter）**：
1. 读取 `typing-data/hsk*.js`（随包内置或下载），按第 2 节解析成 JSON。
2. 题目列表：按级别把每道题的每一行展开成一题，顺序保持（问句在答句前）；乱序时按整道题打乱。
3. 每行渲染成「译文 + 一排空格」：汉字词一个输入框，标点/数字直接显示。
4. 拼音模式的实时转换与判分按第 3 节实现（网页版 `typing.js` 里 `liveConvert`、`parseUser`、`alignPinyin`、`gradePinyin`、`splitAfterWord` 四个函数就是全部算法，可以直接移植；它们只依赖字符串处理）。
5. 汉字模式用系统输入法，注意组合输入期间不处理空格/回车。
6. 录音：按文件名查找，有就自动播放。
7. 记录本地保存：以 `<题目id>:<行号>` 为键。

## 6. 更新题库

词表 Excel 改了以后，按 `tools/typing-data/README.md` 重新生成；题目 id 只和句子中文有关，录音文件名不受影响（中文笔误被修正的句子除外，那几句需要重录）。
