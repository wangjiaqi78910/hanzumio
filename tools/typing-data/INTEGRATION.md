# 汉字打字练习：接入说明（给另一个会话 / 开发者）

这份文档描述 `typing.html` 这个打字练习的全部数据和规则，目的是让另一个会话在不看聊天记录的情况下，把它接进 Hanzumio App（Flutter）或其他产品。所有内容都在仓库 `wangjiaqi78910/hanzumio` 的分支 `claude/chinese-typing-page-gwn6s1` 上。文中的行为描述都对照 `typing.js` 核过；以网页版为准，有出入时以代码为准。

## 1. 现有的东西

| 路径 | 内容 |
| --- | --- |
| `typing.html` `typing.js` `typing.css` | 网页版练习，纯静态、无第三方依赖；但 `typing.html` 还引用站点的 `style.css`（`--ink/--muted/--line/--accent` 等颜色变量）并链接回 `index.html`，单独托管或嵌 WebView 时要一并带上 `style.css`。支持中 / 英 / 韩界面，浅色与深色 |
| `typing-data/hsk1.js` … `hsk7-9.js` | 题库，每级一个文件，共 11,613 道题、22,929 行（句） |
| `audio/hsk1/` … `audio/hsk5/` | 句子录音 MP3，文件名 `<题目id>-<行号>.mp3`；HSK 6、7-9 待补 |
| `audio/README.md` | 录音文件的命名和托管规则 |
| `tools/typing-data/` | 从 HSK 词表 Excel 重建题库的脚本（`README.md` 有步骤） |
| `tools/typing-data/recording/hsk*.txt` | 录音清单：每行「`audio/hsk<级别>/<id>-<行号>.mp3` ⇥ 去掉空格的中文句子」 |

在浏览器里打开 `typing.html` 即可体验（建议通过 HTTP 访问；数据是用 `<script>` 标签按级别动态加载的，个别浏览器对 `file://` 的限制可能影响）。

## 2. 题库数据格式

每个文件是一行 JavaScript：`window.HANZUMIO_TYPING_LEVELS=…;window.HANZUMIO_TYPING_LEVELS["1"]={…};`。去掉第一个 `]=` 之前的内容和末尾的分号，剩下的就是 JSON：

```json
{
  "level": "1",
  "words": {
    "学生": ["xuésheng", "n", "student", "학생"],
    "行|háng": ["háng", "n", "line / profession", "줄 / 직업"]
  },
  "items": [
    ["ce53b631", "d", "爱", [
      ["你 爱 吃 什么 ？", "nǐ ài chī shén-me", "What do you love to eat?", "무엇을 먹는 걸 좋아해요?"],
      ["我 爱 吃 米饭 。", "wǒ ài chī mǐ-fàn", "I love to eat rice.", "저는 밥 먹는 걸 좋아해요."]
    ]]
  ]
}
```

- 级别键固定为 `"1"`、`"2"`、`"3"`、`"4"`、`"5"`、`"6"`、`"7-9"`（文件名 `hsk7-9.js`、录音目录 `hsk7-9`）。各级题数 / 行数：1：602/909，2：210/420，3：783/1565，4：997/1994，5：1599/3198，6：1816/3632，7-9：5606/11211。
- `items` 里每一项：`[id, 类型, 本题词, 行列表]`。
  - id 是 8 位十六进制，由 `normalize.py` 对各行中文（规范化后用 `|` 连接）算 blake2b（4 字节）得到，与类型、本题词、拼音、译文无关；在全部级别内唯一，重建题库时不变。
  - 类型 `d` 是一问一答对话（通常两行，但有 3 道只有一行：HSK1 `368f58c0`、HSK3 `096b6a92`、HSK7-9 `44023afb`），`e` 是例句（一行）。全部 11,613 道题中 d 11,319 道、e 294 道；按行列表的实际长度处理，不要假定 d 一定两行。
  - **一行就是一道题**。网页版把对话的两行拆成前后两题。顶部的「上一题」行显示的是上一道提交过的题（不限于同一对话的问句；例句题前面也可能显示上一道对话的答句）：它的中文（去掉空格）、首次提交结果的 ✓/✗ 和译文；上一题被跳过（没提交）、刚换级别或筛选、「从头再来」、刚打开时不显示；按「上一题」按钮回退时显示的是刚离开的那题。「只练错题」时答句可能单独出现、没有问句。原生实现若要显示问句作上下文，应直接取同一道题的第 0 行，不必照搬网页版。
  - 「本题词」（第 3 个字段）只用于两处：① 提交后，汉字与本题词完全相同的空格和词卡加高亮；本题词只是某个词的一部分时（百 在 一百 里、病 在 生病 里）不高亮，这种题有 1,145 道；② 提交后在题号旁显示「本题词 爱 ài」，拼音取 `words[本题词][0]`（词典拼音，可能带 `/` 多音，如 谁 `shéi/shuí`）；本题词不在 `words` 里时（917 道）只显示汉字。
- 每行：`[w, p, en, ko]`。行号从 0 开始。
  - `w`：句子，词与词之间一个空格。网页版把「含汉字」的词当作要打的词（数据里没有汉字与数字/字母混合的词）；其余固定显示、不要求输入：全角和半角标点（。？，?！“”、《》!：）、数字（2026、101）、字母（HSK、KTV、CEO，以及 `P - I - N - Y - I - N` 里的 `-`）和 `%`。字母/数字用正文色显示，纯标点用灰色且对读屏隐藏。
  - `p`：只给汉字词的拼音，顺序与 `w` 里的汉字词一致；一个词内部音节用 `-` 分开，一个字一个音节；儿化的「儿」写作 `r`（哪儿 → `nǎ-r`）。专有名词的音节首字母大写（`Běi-jīng`、`Wáng Míng`、`Hàn-yǔ`，共 653 个音节）；轻声音节不带调号；ü 写作 ü；`p` 里没有撇号，也没有 `/` 多音（`/` 只出现在 `words` 的拼音值里）。比对不分大小写，显示保留大小写。
  - 显示用拼音由 `p` 生成（`joinPinyin`）：去掉 `-` 直接相连，第二个及以后以 a/e/o（含带调形式）开头的音节前加撇号（Xī'ān、nǚ'ér、Tiān'ānmén、kě'ài），儿化 r 直接相连（nǎr）。这个字符串用于汉字模式的空格提示、提交后的答案行、词卡、「看答案」填入值和输入框宽度。
  - `en` / `ko`：这一行的译文，作为题面。目前每行两种都有。显示哪种由「释义语言」设置（`mean`：en/ko）决定，不是界面语言：默认界面为韩文时用 ko，否则用 en（中文界面也显示英文，没有中文释义）。所选语言为空时退回另一种，都没有时题面显示「…」、词卡释义留空。
- `words`：这一级句子里用到的词的词卡，键是汉字；同形异音的词再加一条 `汉字|拼音`（去掉 `-`、转小写、保留调号，如 `北京|běijīng`）。值固定 4 项 `[拼音, 词性代码, 英文释义, 韩文释义]`。查词时先用 `汉字|该词在这句里的拼音`（把 `p` 里的音节去掉 `-` 并小写），查不到再用 `汉字`；目前句子里每个汉字词都能查到（2,331 次经 `汉字|拼音`，其余经 `汉字`），代码也允许查不到（词性、释义为空）。
- 词性代码：n 名词 v 动词 a 形容词 d 副词 r 代词 m 数词 q 量词 p 介词 c 连词 u 助词 i 叹词 o 拟声词 af 词缀 ci 成语 x 短语（代码还认 mv 能愿动词，数据未用）。
- 文件大小（原始 / gzip）：1：124/41 KB，2：101/41，3：179/61，4：450/185，5：883/378，6：910/400，7-9：3284/1439 KB。网页按级别按需加载。

## 3. 判分规则（网页版的实际行为，接入时请保持一致）

两种输入方式，由用户切换。

### 拼音模式（面向外国学习者，像输入法一样）

- 只打字母即可：`nihao` 算对。**默认不要求声调**。大小写不区分。
- **声调可选**：用数字 `ni3` 标调，输入时实时变成 `nǐ`；标了就检查，标错显示黄色（拼音对、声调错），不标不扣分。
- **实时转换规则**（`liveConvert`）：先 `u:`→`ü`、`U:`→`Ü`、`v`→`ü`、`V`→`Ü`；再对每段「字母串 + 一个数字 0–5」：在字母串末尾找最后一个音节（可选声母 + 元音串 + 可选 n/ng 韵尾 + 可选儿化 r），数字 1–4 把调号标在该音节上，0/5 只去掉数字；找不到音节（`x3`）则原样保留。调号位置：有 a/e 标 a/e，否则 `ou` 标 o，否则标最后一个 i/o/u/ü（liú、jiǔ、xiòng、lǜ）。保留大小写（Ni3→Nǐ）；`nihao3` 只给 hao 标调；`dianr3`→`diǎnr`、`wanr2`→`wánr`。
- **ü**：可以打 `v`、`ü` 或 `u:`。数据里 j q x y 后面的 ü 按标准写作 u（xué、qù、yǔ、jù），用户打 u、v、ü 都算对（比对前把 j/q/x/y 后面的 ü 改成 u，连打分词也用同一规则）；l、n 后面的 ü 数据写作 ü（nǚ、lǜ，共 362 个音节），这时必须打 v/ü/u:，打 `nu` 算写错。
- **儿化**：儿化音节（数据里的 `r`）用户写 `r` 或 `er` 都行，它本身不检查声调。紧跟其后的数字只在前一个音节还没有声调时才算前一个音节的声调（`nar3`、`naer3`、`na3r` 都算对；`na3r4` 的 4 被忽略，也算对；`nar4` 算声调错）。
- **一、不、个** 按字放宽，词内任何位置都适用（一百、不是、第一、一个…）：一 接受 1/2/4 声，不 接受 2/4 声，个 接受 4 声和轻声；放宽的声调与数据里给的声调取并集，其余声调（yi3、bu1、ge1）算声调错。轻声音节（数据里不带调号，如 什么 的 me）：不标、标 5 或标 0 都算对，标 1–4 算声调错。
- **逐字母比对**（`parseUser` + `alignPinyin`）：先 NFC、转小写、`u:`/`v`→`ü`，去掉空白、撇号（' ’ ‘）、反引号、间隔号 `·` 和连字符 `-`；数字 0–5 是声调记号（0 等于 5）；带调号的字母（直接输入或粘贴的 nǐ）拆成字母 + 声调；其他字符（6–9、标点、汉字…）都当作对不上的字母。然后按正确答案的音节逐个消耗：每个音节的字母必须逐一相同，音节内出现数字算写错；音节字母之后紧跟的一个数字是该音节的声调（覆盖字母上的调号；否则音节内第一个带调号的字母决定声调）；全部音节消耗完还有剩余字符算写错（红）。
- **连打规则**（`splitAfterWord` / `overflowPy`，每次输入后）：先对整格做实时转换，再检查内容是否以这个词的正确拼音开头——逐音节比对，不分大小写、忽略调号、v 等同 ü、跳过空白和撇号（' ’，不跳过连字符），每个音节后允许一个 0–5 的数字；前缀匹配且剩余部分以字母（a–z/ü）开头时，剩余部分（经实时转换）接到下一个未看答案的空格内容的前面，并对那个空格重复检查（可连续流过多个空格），焦点停在最后收到字母的空格。前缀不匹配（打错了）或剩余部分以撇号、数字、带调号字母开头时什么都不流。
- **内容里出现空白**（手机键盘空格、粘贴整句，`distributePy`）：按空白拆段，第一段留在当前格，后面各段依次填进后面未看答案的空格（覆盖原内容），空格用完后多余的段追加到最后那格；末尾有空白则焦点移到下一个未看答案的空格。
- **必须写声调**（设置 `toneReq`）：没标调的音节算声调错，除非它的可接受声调含轻声：数据标为轻声的音节、个、以及儿化的 r 本身不标也算对；儿化词的前一个音节仍要标，`nar` 算声调错、`na3r` 算对。

### 汉字模式

- 用系统中文输入法打字。输入法选字时按的空格、回车不能当作「跳词」「提交」（网页版在 `isComposing` / keyCode 229 时不处理键盘事件；输入事件在组合输入期间也不处理，`compositionend` 后补处理一次）。
- 每次输入（组合输入期间除外）：① 内容里出现空白 → 去掉空白，焦点移到下一个未看答案的空格；② 内容含英文字母或不含汉字 → 不处理（留给输入法）；③ 否则去掉空白、标点、符号（`\s`、`\p{P}`、`\p{S}`，NFC）后，字数超过这个词时前 n 个字留下，多出的字接到下一个未看答案的空格内容前面，依次往后流；④ 最后收到字的空格字数已够且后面还有空格时，焦点自动跳到下一个空格（打满一个词自动前进）。
- 判分：去掉空白、标点、符号（数字和字母不去）后与正确汉字完全相同才算对。汉字模式只有 正确 / 写错 / 没写 / 看了答案，没有「声调错」。内容含英文字母时提交会附加提示「汉字模式要用中文输入法」（拼音模式内容含汉字时附加「请用英文键盘」）。

### 通用

- 标点、数字、字母不用打，原样显示。
- 所有空格都空着时提交不判分，只提示「先写答案再提交」。
- 提交后：对的绿、声调错黄、写错或没写红。拼音模式下每个词下面都显示汉字 + 带调拼音；汉字模式下写错/没写的词显示正确汉字 + 拼音，正确和看了答案的词只显示拼音。下方显示每个词的词卡（词性、拼音、释义）：词性按界面语言显示（名词 / noun / 명사），释义按释义语言、缺了退回另一种；本题词高亮。「词卡提示」档位下词卡在提交前就显示在空格上方，提交后按结果着色。
- **记录**：一道题所有词都「正确」（绿）才记为答对；任何一个词声调错、写错、没写或看了答案，整题记为答错。记录在这道题本次显示期间只写一次（之后「再练一遍」不改变）；但重新进入同一道题（上一题、从头再来、换级别后回来、下次打开）再提交会覆盖之前的记录。「跳过」不写记录。切换输入方式会重新渲染当前题（输入清空，记录不变）。
- **看答案**：Esc 作用于焦点所在空格，按钮作用于焦点所在（已看过则第一个没看过的）空格；填入答案（拼音模式填带调拼音如 nǐhǎo，汉字模式填汉字），该空格变只读、连打时字母会跳过它，焦点移到下一个未看答案的空格；提交时记为「看了答案」（红色、虚线下划线），整题记为答错。
- **再练一遍**：清空所有不是「正确」的词（包括看了答案的，并恢复可编辑），焦点放在第一个错词。
- **提示**三档：不提示 / 空格上方提示（拼音模式显示汉字、汉字模式显示拼音；默认）/ 词卡提示。
- **键盘**（组合输入期间、设置对话框打开、按住 Alt/Ctrl/Meta 时一律不处理）：答题中——Enter：在任何空格里都提交（不只是最后一个词）；Space：跳到下一个空格（即使它已看答案），在最后一个空格上提交；Backspace：空格为空或只读时回到上一个空格；←：光标在最前时回到上一个空格；→：光标在最后时去下一个空格（光标放最前）；Esc：看当前空格的答案；Ctrl 单独按（不连发）：任何时候重听录音。提交后——Enter 或 Space（焦点在空格里或页面上）：下一题。手机键盘没有 keydown，空格靠输入内容里出现空白来处理（见连打规则）。
- **本地记录**：`localStorage["hanzumio-typing-v3"]` 是一个 JSON：

  ```json
  { "settings": { "ui": "zh|en|ko", "mean": "en|ko", "mode": "py|hz", "level": "1…6|7-9",
                  "onlyWrong": false, "shuffle": false, "toneReq": false,
                  "hint": "none|cross|cards", "autoPlay": true },
    "results": { "<题目id>:<行号>": "ok|bad" },
    "pos": { "<级别>": "<题目id>:<行号>" },
    "seeds": { "<级别>": 整数 } }
  ```

  题目 id 在全部级别内唯一，所以 results 的键不带级别。默认值：ui 按浏览器语言（ko→ko、zh→zh、其他→en），mean 在 ui 为 ko 时 ko、否则 en，mode py，level "1"，hint cross，autoPlay true，其余 false。「清空记录」只删 results 和 pos，settings 和 seeds 保留。进入一个级别时从 pos 记的题开始，没有则第一道没有记录的题，再没有则第一题。乱序：每级一个随机种子（首次打乱时生成并保存），对 items 做 Fisher–Yates 打乱后再展开成行，顺序跨次打开稳定；「只练错题」在展开后只保留 results 为 bad 的行（保持顺序），为空时显示「还没有错题」。已答对 / 已答错 / 正确率 / 进度条都按当前题目列表计算。

## 4. 录音

- 路径由 `AUDIO_BASE + "hsk" + 当前级别 + "/" + id + "-" + 行号 + ".mp3"` 直接拼接，例如 `audio/hsk1/ce53b631-0.mp3`。`AUDIO_BASE` 默认 `audio/`；自定义时用 `window.HANZUMIO_AUDIO_BASE = 'https://…/'`，必须以 `/` 结尾，并在引入 `typing.js` 之前设置；跨域存储要开 CORS。
- 题目出现时先停掉上一题的录音再 `new Audio()` 预加载；加载出错（404 或任何错误）时隐藏按钮并把这题记进内存集合（不持久化，刷新后会重试）。自动播放受浏览器手势限制，失败时静默。Ctrl 单独按和喇叭按钮都从头重放，按钮点击后焦点回到当前空格。设置里可关闭自动播放。
- 文件：单声道 MP3，24 kHz、48–64 kbps，每个 3–40 KB。HSK1–5 清单 8,086 句、文件 7,834 个、缺 252（1：45，2：5，3：78，4：39，5：85），没有清单外的文件，合计 117 MB；全部约 2.3 万句估计 350 MB。HSK6、7-9 全部待录。缺的清单 = `tools/typing-data/recording/` 的清单与 `audio/` 实际文件的差集。
- App 可以随包内置、或按级别下载。

## 5. 两种接入方式

**A. WebView 嵌入（最快）**：App 内打开托管的 `typing.html`（合并到 `main` 后由 GitHub Pages 发布）。URL 参数可以预设界面：`typing.html?level=2&ui=ko&mean=ko&mode=py&hint=cards&tones=req&autoplay=0&shuffle=1`。规则：level 取 1–6 或原样写 `7-9`；ui：zh/en/ko；mean：en/ko；mode：py/hz；hint：none/cross/cards；tones 只有 `req` 是必须写、其他都是可不写；autoplay 取 0/off/false 为关、其他为开；shuffle 取 1/on/true 为开、其他为关；没有「只练错题」参数。非法值不会沿用已保存的设置，而是退回默认值（`level=8` → 1，`hint=x` → cross）。参数会写进该 WebView 的设置，之后不带参数打开也保持。缺点：练习记录在 WebView 的 localStorage 里，与 App 数据不互通；离线需要自己缓存数据和录音。

**B. 原生实现（Flutter）**：
1. 读取 `typing-data/hsk*.js`（随包内置或下载），按第 2 节解析成 JSON。
2. 题目列表：按级别把每道题的每一行展开成一题，顺序保持（问句在答句前）；乱序时按整道题打乱。
3. 每行渲染成「译文 + 一排空格」：汉字词一个输入框，标点 / 数字 / 字母直接显示。
4. 需要移植的纯字符串函数（都在 `typing.js`，只依赖字符串处理，可以直接移植）：`parseExpected`（把 `p` 的一个词解析成音节：不带调小写字母 `b`、声调 `t`、可接受声调集合 `acc`（含 一/不/个 放宽）、儿化标记 `er`、显示形 `disp`）、`markSyllable`、`liveConvert`、`joinPinyin`、`parseUser`、`alignPinyin`、`gradePinyin`、`splitAfterWord`（及调用它的 `overflowPy`、处理空白的 `distributePy`）；汉字模式用 `cleanHz`、`spillHz`。
5. 汉字模式用系统输入法，注意组合输入期间不处理空格 / 回车。
6. 录音：按文件名查找，有就自动播放。
7. 记录本地保存：以 `<题目id>:<行号>` 为键，含义见第 3 节「本地记录」。

## 6. 更新题库

词表 Excel 改了以后，按 `tools/typing-data/README.md` 重新生成；题目 id 只和句子中文有关，录音文件名不受影响（中文笔误被修正的句子除外，那几句需要重录）。
